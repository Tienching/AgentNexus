# Telemetry Data Retrieval Skill

这是一个专门用于从NOSGPT_TALOS系统获取Telemetry数据的技能。该技能可以根据用户提供的attr配置文件来查找对应的attr_id，并调用NOSGPT_TALOS.get_telemetry_data获取数据。

## 使用方法

1. **调用技能**，告诉我要查询什么属性
2. **提供查询参数**（设备ID、时间范围、端口/组件信息等）
3. **获取Telemetry数据结果**

**注意：** attr配置文件已内置在skill中，包含完整的Talos属性映射关系。

## 内置attr配置文件

skill已内置完整的Talos属性配置文件 `talos_attr_config.csv`，包含100多个属性的映射关系，涵盖：

- **端口流量统计**：入流量、出流量、入包量、出包量、错误包、丢包等
- **设备性能指标**：CPU利用率、内存利用率、设备温度等
- **光模块监控**：发光功率、收光功率、模块温度、激光器温度等
- **缓存统计**：整机缓存、端口缓存、headroom使用情况等
- **VXLAN/隧道统计**：VNI、tunnel相关的各种计数器
- **FEC和光信号质量**：纠错统计、信噪比、通道质量等
- **路由表资源**：地址表、路由表、邻居表使用量等

每个属性都包含详细信息：**属性含义(单位,上报周期,所需标签字段)**

## 必需参数说明

调用NOSGPT_TALOS.get_telemetry_data需要以下参数：

- **attr_id**: 属性ID（从配置文件中查找，必填）
- **start_time**: 开始时间，格式：'YYYY-MM-DD HH:MM:SS'（必填）
- **end_time**: 结束时间，格式：'YYYY-MM-DD HH:MM:SS'（必填）
- **tag_info**: 标签信息，JSON格式，设备标识使用devid字段（必填）
- **period**: 采样周期（秒），默认为60（可选）

**重要提示：**
- 时间格式必须是 'YYYY-MM-DD HH:MM:SS'，不是RFC3339格式
- tag_info中设备标识必须使用 "devid" 而不是 "device"
- tag_info必须是有效的JSON格式
- **数据解读注意**: 某些指标(如MODULE_PRESENT)可能因上报周期(如1分钟或5分钟)显示数值波动，需要查看较长时间数据以确定真实状态，避免将周期性上报误认为异常抖动

## 使用示例

```
我需要查询设备2421658的CPU使用率数据，时间范围是今天上午9点到10点
```

```
请帮我获取设备2421658端口Eth400GE3的入流量数据，时间从2025-10-22 14:56:00到2025-10-22 15:06:00
```

```
查询设备123456的内存使用率，最近1小时的数据
```

**正确的tag_info格式示例：**
- 单一设备：`{"devid": "2421658"}`
- 设备+接口：`{"devid": "2421658", "interface_name": "Eth400GE3"}`
- 设备+CPU：`{"devid": "2421658", "cpu_index": "0"}`

## 技能工作流程（强制执行）

**步骤1: 读取配置文件**
- **必须首先读取**内置的 `talos_attr_config.csv` 文件
- 解析并建立属性名称/描述与attr_id的映射关系
- **严禁跳过此步骤**直接使用已知的attr_id

**步骤2: 属性匹配和查找**
- 根据用户输入的自然语言描述匹配对应的attr_id
- **支持模糊匹配**: 如"模块在位状态"、"在位状态"、"MODULE_PRESENT"都能匹配到attr_id 1000018
- 如果找不到匹配项，向用户询问更具体的描述

**步骤3: 参数收集和验证**
- 收集必需参数：设备ID、时间范围、标签信息
- **自动处理时间格式**: 将自然语言转换为 'YYYY-MM-DD HH:MM:SS' 格式，使用系统命令获取当前时间
- **自动构建tag_info**: 使用devid字段，格式化为JSON
- **缺失参数处理**: 主动询问用户补充必要信息

**步骤4: 执行查询**
- 使用所有参数调用 `mcp__NOSGPT_TALOS__get_telemetry_data`
- **错误处理**: 处理系统繁忙、参数错误等异常情况
- **重试机制**: 遇到"systerm busy"错误时，可尝试重新调用

**步骤5: 结果格式化和分析**
- 格式化返回的时间序列数据
- 提供统计分析（平均值、最大值、最小值）
- **数据解读建议**: 对于状态类指标，说明上报周期影响
- **趋势分析**: 识别数据中的异常模式或抖动

## 执行指令（严格遵循）

当用户请求查询Telemetry数据时：

1. **必须首先读取配置文件**: 使用`Read`工具读取`talos_attr_config.csv`
2. **属性匹配**: 根据用户描述在CSV中查找对应的attr_id行
3. **参数验证**: 确保有设备ID、时间范围等必需参数
4. **时间格式转换**: 将自然语言时间转换为'YYYY-MM-DD HH:MM:SS'
5. **构建查询参数**:
   - attr_id: 从CSV文件查找到的数值（如MODULE_PRESENT对应1000018）
   - tag_info: `{"devid": "设备ID"}`格式
   - start_time/end_time: 转换后的时间格式
6. **执行查询**: 调用`mcp__NOSGPT_TALOS__get_telemetry_data`
7. **结果处理**:
   - 格式化时间序列数据
   - 提供统计分析
   - 识别异常模式
   - 给出数据解读建议

**错误处理流程:**
- 系统繁忙: 等待后重试1-2次
- 参数错误: 检查并修正参数格式
- 无数据: 确认设备ID和时间范围是否正确

**示例正确流程:**
用户: "查询设备2421658的模块在位状态，最近一小时"
1. 读取CSV → 找到MODULE_PRESENT → attr_id 1000018
2. 使用系统命令获取当前时间 → 设置时间范围
3. 构建参数: {"devid": "2421658"}
4. 执行查询 → 格式化结果 → 分析抖动模式

**关键提醒:**
- **严禁跳过CSV读取步骤**，即使知道attr_id
- **严禁直接调用MCP接口**，必须通过技能流程
- **必须验证参数格式**，确保时间格式和JSON格式正确
